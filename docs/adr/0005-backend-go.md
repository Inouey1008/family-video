# ADR-0005: バックエンドは Go にし、1 つのバイナリで動かす

- Status: Accepted
- Date: 2026-11-15

## Context

- 保守に時間をかけない (PRD の Maintenance)。言語ランタイムやコンテナのベースイメージを、定期的に更新する手間を避けたい
- 外部依存を最小限にする (PRD の Maintenance)
- 画面の HTML はサーバーが組み立てる ([ADR-0004](0004-mpa.md))
- サーバーレスで動かす ([ADR-0001](0001-serverless.md))。アクセスがまばらなので、ほとんどのリクエストが起動から始まる (コールドスタート)。課金は処理の時間とメモリの量で決まる
- 業務で使っている言語は TypeScript・C++・Ruby・Java・Swift・Dart。Go は少しわかる程度、Python と Rust はあまり使っていない
- Go のバイナリは起動が速く、メモリも少なくて済むので、コールドスタートが短く、費用も小さい
- 習熟度より、ランタイムの更新が要らないこと・標準ライブラリで足りること・起動が速いことを優先する

## Decision

- バックエンドは Go で書き、依存を含めて 1 つのバイナリにビルドする。
- HTTP・HTML のテンプレート・暗号は標準ライブラリを使う。外部依存は aws-lambda-go・aws-sdk-go-v2・pgx に限る。

## Alternatives

| 案 | 習熟度 | 起動 | 選ばなかった理由 |
|---|---|---|---|
| TypeScript (Node.js) / Ruby | 業務で使う | 普通 | 言語ランタイムの上で動く。ランタイムは数年ごとにサポートが切れ、そのたびに移行が要る。TypeScript は npm のパッケージの間接的な依存が多く、更新と脆弱性の確認が重い |
| Java | 業務で使う | 遅い | 言語ランタイムの上で動き、数年ごとに移行が要る。JVM の起動に時間がかかり、コールドスタートが長い |
| Python | あまり使っていない | 普通 | 言語ランタイムの上で動き、数年ごとに移行が要る |
| C++ | 業務で使う | 速い | 1 つのバイナリにできるが、HTTP・テンプレートに外部のライブラリが要る。メモリ安全ではなく、脆弱性を作り込みやすい |
| Swift | 業務で使う | 速い | 1 つのバイナリにできるが、サーバー向けのエコシステムが小さく、HTTP・テンプレートに外部のパッケージ (Vapor など) が要る |
| Dart | 業務で使う | 速い | 1 つのバイナリにできるが、サーバー向けの AWS の公式 SDK と Lambda のランタイムがなく、コミュニティのパッケージに頼ることになる |
| Rust | あまり使っていない | 速い | 1 つのバイナリにできるが、HTTP・テンプレート・非同期処理に外部の crate が要る |

## Consequences

- Go は少しわかる程度なので、書き始めは慣れる時間がかかる。
- バイナリを動かす場所は [ADR-0006](0006-lambda.md) を参照。
