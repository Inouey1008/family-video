# ADR-0007: フロントエンドは html/template と htmx 2 で作る

- Status: Accepted
- Date: 2026-11-15

## Context

- 画面はサーバーが HTML を組み立てて返す ([ADR-0003](0003-mpa.md))
- 一覧の切り替えなどは、ページ全体を読み直さずに一部だけ差し替えたい
- 外部依存を最小限にし、安定した技術を選ぶ (PRD の Maintenance)

## Decision

- テンプレートは Go 標準の `html/template` にする。値は自動でエスケープされる。
- 一部の差し替えは htmx 2 で行う。htmx は依存のない 1 つの JS ファイルで、ビルドが要らない。2.0.11 に固定し、`/static` から自分で配信する。
- htmx のほかに JS のライブラリは使わない。端末の中の処理は素の JS で書く。

## Alternatives

| 案 | 選ばなかった理由 |
|---|---|
| htmx 4 | 4.0.0 は 2026-08-28 に出たばかりで、htmx のチーム自身もまだ npm の `latest` にしていない (2027 年の予定)。2 系とは互換性のない変更がある (属性の継承・イベント名・履歴の扱い・エラー応答の差し替え) |
| Hotwire Turbo | 部分更新は、専用の要素 (`turbo-frame`) と応答の形式 (Turbo Streams) に合わせて作る。公式の連携は Rails 向け (turbo-rails) が中心 |
| Unpoly | htmx と同じく属性で部分更新できるが、CSP で `eval` を禁じると、属性に書くコールバック (`up-on-...`) に nonce を付ける必要がある |
| 素の JS (`fetch`) | 差し替え・履歴・読み込み中の表示を自分で書くことになり、JS が増える。JS は端末の中の処理に限る方針 ([ADR-0003](0003-mpa.md)) に合わない |
| Alpine.js | CSP の制約がある |

## Consequences

- htmx 2 系は、期限なくサポートが続くと公式に発表されている。4 系への移行は急がず、今回は決めない。
- htmx には 3 系がない。チームが以前「3.0 は出さない」と約束していたため、2 系の次は 4 系になった。
- CSP などの細目は [設計書](../specs/security.md) を参照。
