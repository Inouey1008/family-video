# ADR-0018: 手動の作業はコードにして実行し、対話型のコンソールは設けない

- Status: Accepted
- Date: 2026-11-15

## Context

- データの修正・メンバーの除外・動画の復元など、手動で行う作業がある
- DB と S3 の両方を書き換える作業が多く、片方だけ変えると食い違う
- prod を書き換える操作は、内容を確認してから実行し、記録を残したい

## Decision

- 手動の作業は `cmd/task` のサブコマンドとして書き、PR で確認してから取り込む。アプリと同じコードを使い、DB と S3 の整合を保つ。
- prod では `task.yml` から、リリースのタグを選び、承認を経て実行する。既定はドライランにする。記録は Actions に残る。
- データを見るだけなら、手元の `psql` から、SELECT だけできる DB のロールで接続する。
- 対話型のコンソールと、管理用の Lambda は設けない。

## Alternatives

| 案 | 選ばなかった理由 |
|---|---|
| Rails コンソールのような対話型のコンソール | prod で任意のコードを、確認も記録もなく実行できてしまう。Go には標準の REPL もない |
| 管理用の Lambda | 関数と権限が増え、呼び出す仕組みも別に要る |
| 踏み台のサーバー (EC2 + Session Manager) | サーバーの固定費と保守がかかる |
| `psql` で直接書き換える | 確認と記録がなく、S3 との整合も取れない |

## Consequences

- 一回きりの作業でも、コードを書いて PR とタグを通す手間がかかる。
- 細目は [設計書](../specs/operations.md) を参照。
